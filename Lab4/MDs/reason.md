## 1. Общая идея по ТЗ и роль этой программы

По ТЗ нужно:

* Иметь **контракты** функций:

  * `float SinIntegral(float A, float B, float e);`
  * `int * Sort(const int *array, size_t n);`
* Сделать **две реализации** этих контрактов в двух динамических библиотеках:

  * `libimpl1.so`: метод прямоугольников + пузырьковая сортировка.
  * `libimpl2.so`: метод трапеций + быстрая сортировка (Хоара).
* Реализовать:

  * Программа №1 — линковка с библиотекой на этапе компиляции (статический выбор реализации).
  * Программа №2 — загрузка `.so` во время исполнения через `dlopen/dlsym`.

Код, который ты прислал, — это как раз **программа №2**: интерактивная консольная программа, которая во время работы:

* загружает `.so` файлы,
* достаёт из них указатели на функции `SinIntegral` и `Sort`,
* позволяет по команде `0` переключаться между реализациями,
* по команде `1` считает интеграл,
* по команде `2` сортирует массив.

## 2. Типы и структуры

### 2.1. Указатели на функции

```c
typedef float (*sin_func_t)(float, float, float); // SinIntegral
typedef int *(*sort_func_t)(const int *, size_t); // Sort
```

На уровне системы:

* В памяти программы у тебя есть **таблица символов** динамической библиотеки, где записано, что есть функция `SinIntegral` с определённым адресом.
* `dlsym` (см. ниже) возвращает **адрес функции**, и ты приводишь его к типу `sin_func_t`.
* Переменная типа `sin_func_t` — это просто указатель (адрес в памяти). При вызове
  `libs[current].sin_integral(A, B, e);`
  на уровне машинного кода это превращается в косвенный вызов: `call [адрес из указателя]`.

### 2.2. Структура `Library`

```c
typedef struct {
    const char *path;
    const char *name;
    void *handle;
    sin_func_t sin_integral;
    sort_func_t sort;
} Library;
```

* `path` — путь к `.so`, который передаётся в `dlopen`.
* `name` — "человеческое" описание реализации, для вывода.
* `handle` — абстрактный дескриптор библиотеки, который возвращает `dlopen`:

  * внутри это указатель на структуру динамического загрузчика, где лежит информация о загруженном ELF файле (таблицы символов, адреса секций и т.п.).
* `sin_integral` и `sort` — указатели на функции, заполненные через `dlsym`.

## 3. Разбор вспомогательных функций программы

### 3.1. `parse_ints`

```c
static int parse_ints(char *token, int **out_values, size_t *out_length)
```

Назначение: разобрать список целых чисел из строки после команды `2` и выделить под них память.

Пошагово:

1. **Проверка первого токена**

   ```c
   if (!token) return -1;
   ```

   Если после `2` пользователь не ввёл числа — сразу ошибка.

2. **Первое выделение памяти**

   ```c
   size_t capacity = 8;
   size_t length = 0;
   int *values = malloc(capacity * sizeof(int));
   ```

   * Выделяется буфер на 8 целых чисел на **куче** (heap).
   * `malloc` внутри:

     * обращается к аллокатору (glibc `ptmalloc` или аналог),
     * тот может дернуть системные вызовы `brk` или `mmap`, чтобы расширить участок памяти процесса.

3. **Цикл по токенам**

   ```c
   while (token) {
       char *endptr = NULL;
       long value = strtol(token, &endptr, 10);
       ...
       token = strtok(NULL, " \t\r\n");
   }
   ```

   * `strtol`:

     * разбирает строку как десятичное число,
     * записывает адрес первого неиспользованного символа в `endptr`.
   * Проверка:

     ```c
     if (endptr == token || *endptr != '\0') { ... }
     ```

     * Если `endptr == token`, значит, число вообще не распарсилось.
     * Если `*endptr != '\0'`, значит, в токене есть лишние символы, не являющиеся частью числа (ошибка формата).
   * Если нужно больше места:

     ```c
     if (length == capacity) {
         capacity *= 2;
         int *tmp = realloc(values, capacity * sizeof(int));
     }
     ```

     * `realloc`:

       * может либо расширить текущий блок на месте,
       * либо выделить новый блок, скопировать туда данные и освободить старый.
   * Сохранение:

     ```c
     values[length++] = (int)value;
     ```

4. **Обработка случая с нулём чисел**

   ```c
   if (length == 0) {
       free(values);
       return -1;
   }
   ```

5. **Выходные параметры**

   ```c
   *out_values = values;
   *out_length = length;
   return 0;
   ```

   На уровне соглашений:

   * Функция возвращает `0` при успехе, `-1` при ошибке.
   * Результат (массив и длина) возвращаются по указателям.

### 3.2. `print_sorted`

```c
static void print_sorted(const int *values, size_t length)
```

* Печатает массив в формате `n1 n2 n3 ...`:

  ```c
  for (size_t i = 0; i < length; ++i) {
      if (i) putchar(' ');
      printf("%d", values[i]);
  }
  putchar('\n');
  ```

* `putchar` и `printf` работают через буфер stdout:

  * Хранят символы в буфере,
  * Буфер сбрасывается (`write` в файловый дескриптор 1) при:

    * `\n` на терминале,
    * `fflush(stdout)`,
    * заполнении буфера,
    * завершении программы.

### 3.3. `load_library`

```c
static int load_library(Library *lib)
```

Главный "системный" кусок, который реализует динамическую загрузку.

1. **Загрузка файла `lib->path`**

   ```c
   lib->handle = dlopen(lib->path, RTLD_LAZY);
   if (!lib->handle) {
       fprintf(stderr, "Failed to load %s: %s\n", lib->path, dlerror());
       return -1;
   }
   ```

   * `dlopen`:

     * открывает ELF файл `.so`,
     * мапит его в адресное пространство процесса (через `mmap`),
     * читает таблицы динамических секций и символов,
     * выполняет **релокации**: подставляет реальные адреса функций/данных в таблицы GOT/PLT,
     * добавляет библиотеку в список загруженных для этого процесса.
   * Флаг `RTLD_LAZY`:

     * символы (функции) реально подставляются только при первом вызове через PLT (ленивая привязка).
   * В случае ошибки `dlerror()` вернёт строку с описанием (например, "cannot open shared object file").

2. **Получение указателя на `SinIntegral`**

   ```c
   dlerror();
   lib->sin_integral = (sin_func_t)dlsym(lib->handle, "SinIntegral");
   const char *err = dlerror();
   ```

   * `dlerror()` до `dlsym` — чтобы сбросить предыдущую ошибку.
   * `dlsym` ищет в таблице символов загруженной библиотеки экспортируемый символ `"SinIntegral"`:

     * если находит — возвращает **адрес функции**,
     * если нет — устанавливает внутреннюю ошибку, которую можно прочитать через `dlerror()`.
   * При ошибке:

     ```c
     fprintf(stderr, "Failed to resolve SinIntegral in %s: %s\n", lib->path, err);
     dlclose(lib->handle);
     lib->handle = NULL;
     return -1;
     ```

3. **Получение указателя на `Sort`**

   Аналогично `SinIntegral`:

   ```c
   lib->sort = (sort_func_t)dlsym(lib->handle, "Sort");
   ...
   ```

4. **Успешный возврат**

   ```c
   return 0;
   ```

На уровне системы:

* После `load_library` в структуре `Library`:

  * `handle` указывает на структуру динамического линковщика.
  * `sin_integral` и `sort` содержат адреса в памяти, где реально находится код этих функций в загруженной `.so`.

### 3.4. `unload_library`

```c
static void unload_library(Library *lib)
{
    if (lib->handle) {
        dlclose(lib->handle);
        lib->handle = NULL;
        lib->sin_integral = NULL;
        lib->sort = NULL;
    }
}
```

* `dlclose` уменьшает счётчик ссылок на `.so`:

  * когда счётчик достигает нуля, динамический загрузчик может:

    * удалить записи о символах,
    * unmap-нуть сегменты библиотеки из адресного пространства (через `munmap`).
* После этого адреса в `sin_integral` / `sort` становятся **недействительными**, поэтому их обнуляют — защита от случайных вызовов.

## 4. Разбор `main` по шагам

### 4.1. Инициализация библиотек

```c
Library libs[] = {
    {.path = "./libimpl1.so", .name = "rectangles + bubble sort",
     .handle = NULL, .sin_integral = NULL, .sort = NULL},
    {.path = "./libimpl2.so", .name = "trapezoids + quicksort",
     .handle = NULL, .sin_integral = NULL, .sort = NULL},
};
const size_t lib_count = sizeof(libs) / sizeof(libs[0]);
```

* Массив из двух реализаций, каждая с:

  * своим `.so` файлом,
  * описанием (как по ТЗ: прямоугольники+пузырёк, трапеции+быстрая).

```c
size_t current = 0;
int exit_code = 0;
char line[1024];
```

* `current` — индекс активной библиотеки (0 или 1).
* `line` — буфер для чтения строки команды из stdin.

### 4.2. Начальная загрузка активной библиотеки

```c
if (load_library(&libs[current]) != 0) {
    return 1;
}
```

* Загружаем по умолчанию первую реализацию (`libimpl1.so`).
* Если не удалось — программа сразу завершается с кодом `1`.

### 4.3. Вывод справки

```c
printf("Dynamic linking demo ...\n");
...
```

Просто информирование пользователя о возможных командах:

* `0` — переключить библиотеку.
* `1 A B e` — интеграл `sin(x)` на `[A,B]` с шагом `e`.
* `2 nums...` — сортировка чисел.
* `q/exit` — выход.

### 4.4. Главный цикл обработки команд

```c
while (printf("> "), fflush(stdout), fgets(line, sizeof(line), stdin)) {
    ...
}
```

Тут трюк с запятой:

* `printf("> ")` — печать промпта.
* `fflush(stdout)` — сброс буфера, чтобы `>` точно появилось на экране.
* `fgets(...)` — чтение строки:

  * возвращает `NULL` при EOF/ошибке → цикл заканчивается.

#### 4.4.1. Разбор первой лексемы — команды

```c
char *command = strtok(line, " \t\r\n");
if (!command) {
    continue;
}
```

* `strtok`:

  * находит первую "словообразующую" последовательность до любого из разделителей `" \t\r\n"`.
  * заменяет найденный разделитель на `'\0'` в исходной строке.
  * возвращает указатель на начало токена.
* Если пользователь просто нажал Enter — `command == NULL`, пропускаем итерацию.

#### 4.4.2. Обработка выхода

```c
if (strcmp(command, "q") == 0 || strcmp(command, "exit") == 0) {
    break;
}
```

* `strcmp` сравнивает строки посимвольно, пока не встретит `'\0'`.

#### 4.4.3. Команда `0` — переключение библиотеки

```c
if (strcmp(command, "0") == 0) {
    size_t next = (current + 1) % lib_count;

    unload_library(&libs[current]);
    if (load_library(&libs[next]) != 0) {
        fprintf(stderr, "Failed to switch to %s\n", libs[next].path);
        exit_code = 1;
        break;
    }

    current = next;
    printf("Switched to: %s\n", libs[current].name);
    continue;
}
```

Логика:

1. Вычисляем индекс следующей реализации (`0 -> 1`, `1 -> 0`).
2. Выгружаем текущую (чтобы не держать в памяти лишнее).
3. Пытаемся загрузить новую:

   * если не получилось — сообщаем и выходим.
4. Переключаем `current` и выводим информацию.

На уровне системы:

* При `unload_library` → `dlclose`:

  * библиотека может быть полностью выгружена (`munmap`).
* При `load_library` → `dlopen`:

  * библиотека снова мапится в адресное пространство,
  * ей выделяются новые адреса (могут отличаться от предыдущих),
  * заново выполняются релокации.

#### 4.4.4. Команда `1` — вычисление интеграла

```c
if (strcmp(command, "1") == 0) {
    char *a_str = strtok(NULL, " \t\r\n");
    char *b_str = strtok(NULL, " \t\r\n");
    char *e_str = strtok(NULL, " \t\r\n");
    if (!a_str || !b_str || !e_str) {
        printf("Usage: 1 A B e\n");
        continue;
    }
    float A = strtof(a_str, NULL);
    float B = strtof(b_str, NULL);
    float e = strtof(e_str, NULL);
    float result = libs[current].sin_integral(A, B, e);
    printf("Integral: %.6f\n", result);
}
```

Разбор:

1. `strtok(NULL, ...)` — продолжает разбор той же строки:

   * возвращает следующий токен (число).
2. Проверка на наличие трёх аргументов.
3. `strtof`:

   * преобразует строку в `float` (учитывает формат с точкой, экспонентой и т.п.).
   * Вторая переменная (`endptr`) тебе не важна, но в случае некорректного ввода могли бы проверить ошибки.
4. Вызов:

   ```c
   float result = libs[current].sin_integral(A, B, e);
   ```

   На уровне алгоритма (согласно ТЗ):

   * В `libimpl1.so`:

     * `SinIntegral` реализована методом **прямоугольников**:

       * разбивает [A,B] на шаги по `e`,
       * суммирует `sin(x_i) * e` (левые/правые/средние прямоугольники — зависит от реализации).
   * В `libimpl2.so`:

     * методом **трапеций**:

       * на каждом шаге `[x_i, x_{i+1}]` рассчитывает площадь трапеции:
         [
         S_i = \frac{sin(x_i) + sin(x_{i+1})}{2} \cdot h
         ]
       * суммирует.

   Важно: программа **ничего не знает** о внутреннем алгоритме — она только доверяет контракту `float SinIntegral(float A, float B, float e)`.

#### 4.4.5. Команда `2` — сортировка

```c
else if (strcmp(command, "2") == 0) {
    int *values = NULL;
    size_t length = 0;

    if (parse_ints(strtok(NULL, " \t\r\n"), &values, &length) != 0) {
        printf("Usage: 2 n1 n2 n3 ...\n");
        continue;
    }

    int *sorted = libs[current].sort(values, length);
    if (!sorted) {
        printf("Sort failed\n");
        free(values);
        continue;
    }

    print_sorted(sorted, length);
    free(sorted);
    free(values);
}
```

Разбор:

1. `parse_ints` получает **первый токен** после `2` и парсит все числа:

   * выделяет массив `values` на куче,
   * записывает туда все числа.

2. Вызов сортировки через указатель на функцию:

   ```c
   int *sorted = libs[current].sort(values, length);
   ```

   С точки зрения контракта:

   * На вход: указатель на исходный массив и длина.
   * На выход: указатель на отсортированный массив (чаще всего — новый блок памяти, выделенный внутри библиотеки).

   По ТЗ:

   * В `libimpl1.so`:

     * сортировка **пузырьком**:

       * вложенные циклы,
       * попарное сравнение `array[j]` и `array[j+1]`,
       * обмен, если нарушен порядок.
   * В `libimpl2.so`:

     * **быстрая сортировка Хоара**:

       * рекурсивный (или стековый) алгоритм:

         * выбор опорного элемента,
         * разделение массива на "меньше" / "больше",
         * рекурсивная сортировка подмассивов.

   Как и с интегралом — вызывающий код не знает алгоритма, он просто доверяет контракту.

3. Печать и освобождение памяти:

   ```c
   print_sorted(sorted, length);
   free(sorted);
   free(values);
   ```

   * Здесь предполагается, что:

     * библиотека выделяет `sorted` через совместимый с `free` аллокатор (стандартный `malloc`/`free` из той же glibc),
     * поэтому `free(sorted);` корректен.
   * `values` освобождается, потому что был выделен `parse_ints`.

### 4.5. Завершение программы

```c
for (size_t i = 0; i < lib_count; ++i) {
    unload_library(&libs[i]);
}

return exit_code;
```

* На всякий случай выгружаются все библиотеки, если какая-то осталась загруженной.
* Возвращаем код завершения (0 или 1).

На уровне системы:

* Завершение процесса через `return` из `main`:

  * фактически вызывает `exit(exit_code)`,
  * `exit`:

    * вызывает деструкторы статических/глобальных объектов (в C мало актуально),
    * вызывает handlers `atexit`,
    * закрывает файловые дескрипторы,
    * освобождает виртуальную память (включая все маппинги библиотек),
    * ядро удаляет процесс и отдаёт родителю код завершения.

## 5. Как это соответствует ТЗ

1. **Контракты**:

   * Заданы в `contracts.h`, а в коде используются через типы `sin_func_t` и `sort_func_t`.
   * Программа опирается только на сигнатуры, а не на реализацию.

2. **Две реализации**:

   * `libimpl1.so` — `rectangles + bubble sort`.
   * `libimpl2.so` — `trapezoids + quicksort`.

3. **Динамическая загрузка (программа №2)**:

   * `dlopen` / `dlsym` / `dlclose` используются как требует ТЗ.
   * Переключение реализаций по команде `0` реализовано.

4. **Пользовательский ввод**:

   * Команда `0` — переключить реализацию (требование выполнено).
   * Команда `1 arg1 arg2 arg3` — вызов первой функции (`SinIntegral`).
   * Команда `2 arg1 arg2 ...` — вызов второй функции (`Sort`).

5. **Анализ двух типов использования библиотек**:

   * Этот код — "чистый" пример **динамического выбора реализации в runtime**.
   * Для программы №1 у тебя будет обычная линковка:

     * `gcc main.c -L. -limpl1` (например),
     * без `dlopen/dlsym`,
     * выбор реализации фиксируется на этапе линковки и не может быть изменён во время выполнения.
