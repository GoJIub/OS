# Морской бой на общей памяти

Консольный клиент–серверный «Морской бой» с IPC через POSIX shared memory и семафоры. Сервер запускается один раз, клиенты подключаются, регистрируются логином и создают/присоединяются к играм или приглашают друг друга по логину.

## Сборка и запуск
- Сборка: `make`
- Сервер: `./server` (фоновый процесс, логика внутри, без интерактивного ввода)
- Клиент: `./client` (текстовое меню). Для игры нужны два клиента.
- Остановка сервера: `Ctrl+C`

## Архитектура IPC
- Shared memory `SHM_NAME` (`/battleship_shm_v1`) содержит `SharedState`.
- Семафоры:
  - Глобальный `SEM_REQUEST_NAME` (`/bship_req_v1`) — сигнал «появился запрос».
  - Пер-слотные `SEM_SLOT_PREFIX` (`/bship_slot_v1_<n>`) — критсек слота при чтении/записи.
  - Пер-слотные `SEM_RESP_PREFIX` (`/bship_resp_v1_<n>`) — уведомление клиенту, что ответ готов.

### SharedState
- `players[MAX_PLAYERS]` (8): активность, логин, текущий `game_id` (или -1).
- `games[MAX_GAMES]` (8): имя, два слота игроков, чей ход, готовность, счетчик корабельных клеток, победитель, доски 8×8 для обоих.
- `invites[MAX_INVITES]` (16): от кого/кому/в какую игру.
- `requests[MAX_PLAYERS]` и `responses[MAX_PLAYERS]`: почтовые ящики «клиент → сервер» и «сервер → клиент».
- `request_ready[MAX_PLAYERS]`: флаг наличия запроса в слоте.

### Request / Response
- `Request`: `type` (enum `RequestType`), `from_slot`, координаты (`arg1`=x, `arg2`=y), `text` (логин/имя игры), `target_slot` (не используется).
- `Response`: `code` (0 ок, 1 ошибка, 2 инфо), `message`, `game_id`, `your_turn`, `winner_slot`, `has_boards`, ваши/вражеские доски.
  - Вражеская доска содержит только HIT/MISS (корабли скрыты).

## Протокол взаимодействия
1. Клиент находит свободный слот (нет `active` и `request_ready`) и отправляет `REQ_REGISTER` с логином.
2. Для каждого действия клиент:
   - Лочит свой слот семафором, кладет `Request`, ставит `request_ready=1`, отпускает.
   - Поднимает `SEM_REQUEST_NAME`.
   - Ждет `SEM_RESP_PREFIX[slot]`.
   - Читает `Response` из своего слота.
3. Сервер:
   - Ждет `SEM_REQUEST_NAME`.
   - Обходит слоты, где `request_ready`, выполняет обработчик, кладет `Response`, сбрасывает флаг, поднимает `SEM_RESP_PREFIX[slot]`.

## Логика сервера по типам запросов
- `REQ_REGISTER`: проверка уникальности логина и пустого слота, пометка `active`, `game_id=-1`.
- `REQ_LIST_GAMES`: строкой возвращает активные игры с числом игроков и отметкой «finished», если есть победитель.
- `REQ_CREATE_GAME`: создает игру, садит игрока в seat 0, авторасстановка кораблей, готовность=1, ждет второго.
- `REQ_JOIN_GAME`: садит во второй слот существующей игры, авторасстановка, случайно выбирает, кто ходит первым.
- `REQ_SEND_INVITE`: из своей игры с пустым вторым местом отправляет приглашение другому логину.
- `REQ_LIST_INVITES`: возвращает входящие приглашения.
- `REQ_ACCEPT_INVITE`: принимает приглашение (по логину пригласившего или первый найденный), садит во второй слот, авторасстановка, стартует игру.
- `REQ_DECLINE_INVITE`: отклоняет (все либо по логину пригласившего).
- `REQ_GAME_STATUS`: возвращает доски, чей ход, победителя.
- `REQ_FIRE`: проверяет ход/координаты/завершенность, отмечает HIT/MISS, уменьшает `ships_left` соперника, при 0 фиксирует `winner_slot`, переключает ход.
- `REQ_QUIT_GAME`: покидает игру; если соперник есть и победителя нет — ему засчитывается победа; пустая игра сбрасывается и инвайты к ней чистятся.
- `REQ_LOGOUT`: quit + очистка слота игрока и его инвайтов.

## Правила игры
- Поле 8×8, корабли раскладываются автоматически при входе в игру:
  - Длина: 4, 3, 3, 2, 2 (5 кораблей).
- Ходы по очереди; после любого выстрела ход переходит (даже после попадания).
- Победа: все клетки кораблей соперника подбиты.

## Жизненный цикл
- Клиент: `register → (create | join | accept invite) → fire/status/quit → logout`.
- Игра: активируется при создании, запускается при появлении второго игрока, завершается при победителе или выходе обоих.
- Инвайты: удаляются при выходе игрока, принятии/отклонении или удалении игры.

## Меню клиента (что выбрать)
- `1` Список игр
- `2` Создать игру (указать имя)
- `3` Присоединиться к игре по имени
- `4` Отправить приглашение (нужна своя игра с пустым местом)
- `5` Показать приглашения
- `6` Принять приглашение (логин пригласившего или Enter для первого)
- `7` Отклонить приглашения (все или по логину)
- `8` Статус игры / показать поля
- `9` Выстрел (`x y` от 1 до 8 → внутренне 0-based)
- `10` Покинуть игру
- `0` Выход из клиента (logout)

## Ограничения и заметки
- `MAX_PLAYERS=8`, `MAX_GAMES=8`, `MAX_INVITES=16`.
- Сервер не печатает игровую информацию — только обслуживает запросы. Вся визуализация на стороне клиента.
- Если сервер перезапустить: старые IPC очищаются при старте, но клиентов нужно запускать заново.

## Быстрый сценарий проверки
1. Терминал 1: `./server`
2. Терминал 2: `./client`
   - Введите логин, `2` → имя игры, получите «Ждите соперника».
3. Терминал 3: `./client`
   - Другой логин, `3` → имя игры из шага 2.
4. Оба клиента: `8` (статус/поля), затем `9` (выстрелы); игра заканчивается при победителе. `0` — выход.
